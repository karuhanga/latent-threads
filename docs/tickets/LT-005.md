# LT-005 — Implement the schema, validator and graph data loader

[Live kanban card](https://app.notion.com/p/3d907031acb5819e9194ee36a72da45a?pvs=204) · Wave 1 · B — Follow a song

## Objective
Turn the reviewed contract into dependable data that every feature can query.
## Scope
Typed normalized JSON schema with a version; validator; loader; entity lookup; adjacency and contribution queries; one small illustrative development fixture. Keep browser reads behind a thin module.
## Acceptance criteria
- [ ] Reject duplicate IDs, dangling references, invalid relationship endpoint types and contribution/stage/endeavor mismatches.
- [ ] Enforce required provenance/claim status and resource access/license distinctions for release content; illustrative fixtures cannot silently enter the release catalog.
- [ ] Validate geographic containment and unknown semantics; allow optional temporal fields as specified.
- [ ] Provide bounded neighborhood, stage contributions and text-search input queries with deterministic results.
- [ ] CLI/CI validation gives record-level errors and runs against the actual release dataset; test at least the failure cases above.
## Dependencies
[LT-002](LT-002.md), [LT-003](LT-003.md)
## Verification
Run validator on good and deliberately invalid fixtures and meaningful unit tests for traversal/context behavior.
## Out of scope
No Postgres, SQLite runtime, generic database abstraction, bulk importer or full-text engine.
