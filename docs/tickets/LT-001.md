# LT-001 — Establish project scope, kanban and delivery rules

[Live kanban card](https://app.notion.com/p/3d907031acb581a69449f4ae28ff441a?pvs=204) · Wave 1 · A — Visual foundation

## Objective
Turn the ideation into an actionable first release and visible, ordered delivery system.
## Scope
Create the repository product scope, delivery plan, decisions and durable context, plus a Notion tracking hub; real kanban views; first-wave tickets; compact future backlog; tooling/access inventory and Git baseline.
## Acceptance criteria
- [ ] All 11 Wave 1 tickets have acceptance criteria, owner role, size, priority, checkpoint and explicit dependency relations.
- [ ] Kanban supports Backlog → Ready → In progress → In review → Done and a separate Blocked state; a Needs input view exposes only actionable user dependencies.
- [ ] Product scope states three demonstrable checkpoints and the deferred features; a decision record explains bundled JSON/static hosting.
- [ ] Project files link back to the Notion hub; Lincoln’s initial ideation commit is preserved and the planned dist deployment excludes raw docs.
## Dependencies
None.
## Verification
Fetch the database and saved views; query task rows and inspect relation targets; compare local planning links and Git status.
## Out of scope
No app functionality is implied by completing this ticket.
## Handoff
Ticket status and acceptance evidence are tracked in Notion; these unchecked boxes define the contract, not a live progress mirror.
Planned role: PM. Size: S — up to half day. Estimates indicate focused engineering effort, not a calendar commitment.
When starting, set an actual Agent, move to In progress and name files owned. For review, attach exact changed files/commit, relevant check results and a visible preview when applicable. PM checks acceptance before Done.
