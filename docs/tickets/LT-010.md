# LT-010 — Verify and review the first complete playable release

[Live kanban card](https://app.notion.com/p/3d907031acb581c3b63fd6f5d55fd44a?pvs=204) · Wave 1 · C — Discover and learn

## Objective
Demonstrate that discovery, explanation and learning form a coherent usable loop.
## Scope
Run the five-minute product walkthrough, meaningful end-to-end checks, source/content sampling, mobile/keyboard/reduced-motion QA and production subpath verification. Fix release-blocking issues and record remaining polish separately.
## Acceptance criteria
- [ ] A PM walkthrough discovers two different contributions, explains a relationship, reaches an unfamiliar concept, opens a relevant learning resource and returns without losing orientation.
- [ ] Type/data checks and relevant unit/end-to-end tests pass on the exact reviewed revision; invalid IDs, empty search and back/refresh are covered.
- [ ] Inspect at 360px and desktop in a real browser, including keyboard and reduced-motion behavior; no critical overlap, inaccessible control or broken link in the core path.
- [ ] Measure and record initial transfer size and basic interaction timing; investigate avoidable bloat (target core compressed assets/data under 1 MB) rather than claiming unmeasured performance.
- [ ] Attach commit, local preview steps, screenshots and a short release note. Request optional feedback from Lincoln; record real feedback only if obtained.
- [ ] State local-demo readiness separately from public deployment; LT-011 can remain externally blocked without claiming the site is live.

## Verification
Evidence bundle: check commands/results, browser walkthrough, measurements and issues triage. PM makes the release acceptance decision.
## Out of scope
No arbitrary coverage percentage target, comprehensive user study or unsupported launch-date promise.
## Handoff
Ticket status and acceptance evidence are tracked in Notion; these unchecked boxes define the contract, not a live progress mirror.
Planned role: Quality. Size: M — about 1 day. Estimates indicate focused engineering effort, not a calendar commitment.
When starting, set an actual Agent, move to In progress and name files owned. For review, attach exact changed files/commit, relevant check results and a visible preview when applicable. PM checks acceptance before Done.
